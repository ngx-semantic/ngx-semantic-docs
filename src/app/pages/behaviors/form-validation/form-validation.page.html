Usage

Specifying Validation Rules

Pass validation rules for each field to suiFields. Fields are matched by their id, name or data-validate attribute, in that order

Rules can be written in shorthand, as a rule name or a list of rule names.

Longhand Rules

Rules can also be written in longhand, which lets you set the identifier and a custom prompt for each rule

Passing Parameters to Rules

Rules usually take a parameter in brackets, like minLength[2]. If brackets are awkward, pass the parameter as value instead

Customizing Prompts

Set prompt on a rule to replace the default message. Prompts can use the templates {name}, {identifier}, {value} and {ruleValue}, or be a function of the field value

Matching Fields

Use identifier when a field's key should not be used to find it, or match fields with a data-validate attribute when the server needs a specific name

Validating on Blur and Other Events

Set suiInline to show errors in a label next to each field, and suiOn to validate on blur or change instead of submit

Dependent Fields

Add depends with the identifier of another field to only validate a field when that other field has a value

Optional Fields

Add optional: true to only validate a field when it is not empty

Validating Programmatically

Export the directive with #ref="suiFormValidation" to validate, read and write values, reset or clear the form

reset() restores the values the fields had when the form was first validated.

Reactive Forms

suiFormValidation works with [formGroup] and ngModel. Rule failures are added to the matching control's errors under the suiFormValidation key, next to any Angular validator errors

With reactive forms, the input's id or name must match the field identifier so errors can be shown next to it.

Rules

Empty

Check that a field has a value, or that a checkbox is checked

Content Type

Inputs can match common content types, or your own regular expression

Payment

Inputs can validate credit card numbers, optionally limited to some card types

Supported types are visa, amex, mastercard, discover, unionpay, jcb, dinersClub, maestro, laser and visaElectron.

Matching Fields

Fields can be required to match, or differ from, other fields

Length

Inputs can match against the length of their content

Specified Content

Rules can specify content that should or should not appear in an input

Selection Count

Multiple selects can specify how many options should be chosen
suiFormValidation is part of SuiFormModule from ngx-semantic/collections/form. Use it on a <form> together with sui-form.

Methods

Method Description
validateForm() Validates the whole form, shows errors and emits suiOnSuccess or suiOnFailure. Returns whether the form is valid
validateField(identifier) Validates one field and shows its error. Returns whether it is valid
isValid(identifier?) Returns whether the form, or one field, passes its rules without updating the UI
getFieldElement(identifier) Returns the element matching an id, name or data-validate value
getValue(identifier) Returns the value of a field
getValues(identifiers?) Returns the values of the given fields, or of every validated field
setValue(identifier, value) Sets the value of a field
setValues(values) Sets several field values from an object
reset() Restores every field to the value it had when the form was first validated
clear() Clears every field in the form
getAngularForm() Returns the FormGroup of a [formGroup] or NgForm on the form, if there is one

Rules

Rule Description
empty A field is not empty
checked A checkbox field is checked
email A field is a valid e-mail address
url A field is a url
integer A field is an integer, or in a range: integer[1..10]
decimal A field is a decimal number
number A field is any number, decimal or not
regExp[expression] A field matches a regular expression: regExp[/^[a-z0-9_-]{3,16}$/]
creditCard A field is a valid credit card, optionally of some types: creditCard[visa,mastercard]
contains / containsExactly A field contains text, case insensitive or sensitive: contains[foo]
doesntContain / doesntContainExactly A field does not contain text: doesntContain[foo]
is / isExactly A field is a value: is[foo]
not / notExactly A field is not a value: not[foo]
minLength / exactLength / maxLength A field's length: minLength[5]
match / different A field matches, or differs from, another field: match[password]
minCount / exactCount / maxCount A multiple select has a number of selections: minCount[2]
